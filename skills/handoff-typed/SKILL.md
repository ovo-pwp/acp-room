# handoff-typed — 交接要带类型

## 为什么

自由文本交接是多 agent 系统里**最常见、也最不容易被发现的失败**：
接收方推断意图、猜边界，猜错了不会报错，而是**自信地答了另一件事**。

任务本身不贵，返工贵。

## 最小三要素（缺一条就不许发）

```json
{
  "task": "一句话，动词开头，说清要产出什么",
  "bounds": ["不许做什么", "只能用哪些来源", "范围到哪为止"],
  "good_answer_looks_like": "什么样的回答算完成：格式、长度、必须包含什么"
}
```

| 要素 | 反例 | 正例 |
|---|---|---|
| task | "看看这个项目" | "列出 acp-room 里所有调用 request_permission 的位置，给出文件:行号" |
| bounds | （空） | "只读，不要改文件；只看 acp-room/ 目录" |
| good_answer_looks_like | （空） | "表格：文件、行号、触发条件；找不到就写找不到" |

## 四条铁律（都来自实测踩坑）

1. **被寻址者必须在你可见的名册里**。你问不到一个人问不到的 bot。
2. **答案落点由平台决定，不能由你决定**。你不许指定"把结果写进某个会话"。
3. **你不许自称是别的 agent**。身份由平台盖章。
4. **有接收上限**。一次 run 里不要连发多个交接，深度有上限，超了会被拒绝——**拒绝，不是截断**。

## 交接失败要说出来

如果交接发出去了、没回来，**必须回到你或人在看的那个会话里明说"没回来"**，
不许让对话就这么停住——一个没人回的问题和一个慢问题看起来一模一样。

## 什么时候该找人而不是找 agent

- 需要**判断力**而不是信息 → 找人（`ask_person`）
- 需要**信息**且只有别人知道 → 找 agent
- 两个都不确定 → 找人。找人成本低，叫醒另一个 agent 要一次完整模型调用

## 和人交接的格式

```
我需要你决定的：<一个具体问题，不要开放式的"怎么办">
为什么我定不了：<缺什么信息或什么权限>
你不回话的后果：<我接下来会怎么处理>
```
