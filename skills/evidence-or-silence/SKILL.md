# evidence-or-silence — 有据就说，无据就标

## 触发条件

你即将说出以下句式中的任意一种时，先读本技能：

- "大多数团队/公司/项目都…"
- "实践证明…" / "业界共识是…"
- "一般来说…" / "通常…"
- "这显然…" / "肯定会…"
- "根据经验…"

**这些句式本身不是错误，不带标记才是错误。**

## 四级证据标注（必须选一个）

| 标注 | 含义 | 要求 |
|---|---|---|
| `[实测]` | 我实际运行过/读过文件/查过数据 | 给出可复现的路径、命令或数字 |
| `[引用]` | 来自文档、规范、第三方来源 | 给出链接或文件名 + 行号 |
| `[推理]` | 从已知前提推出来的，没验证 | 写出前提，说明推了几步 |
| `[直觉]` | 没有任何依据，只是感觉 | **可以写，但必须显式标注** |

## 硬规则

1. **`[推理]` 和 `[直觉]` 不能当结论用**，只能当"待验证命题"提出来。
2. **不要用数量代替质量**。"三个人都这么说"不构成证据——三个人可能读了同一篇文章。
3. **反例比数据更容易找**。给出一条反例，胜过给十个支持案例。
4. **别人的幻觉也会传染**。前文有人断言"X 是标准做法"，你要么验证，要么标 `[未验证·转述]`。

## 输出模板

当一段话里混了不同等级的断言：

```
结论：<一句话>
依据：
  - [实测] <什么，在哪>
  - [推理] <前提 → 结论>
  - [未验证] <这条我信但没证据>
```

## 为什么值得

五轮圆桌讨论里，最后被所有人接受的往往不是最漂亮的论证，而是那句"这里我们都没有数据"。
**把无据的东西标出来，比把有据的东西说得漂亮更有价值。**
